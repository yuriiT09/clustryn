# Contributing

Thank you for your interest in contributing to Clustryn.

## Workflow

1. Create or select an Issue.
2. Create a branch for the change.
3. Implement one focused change.
4. Add or update tests where appropriate.
5. Open a Pull Request.
6. Merge only after all required checks pass.

## Branch Naming

Use clear branch names with one of the following prefixes:

- `feature/` — new functionality
- `fix/` — bug fixes
- `docs/` — documentation changes
- `test/` — testing changes
- `research/` — technical investigation
- `refactor/` — code restructuring without changing behaviour
- `chore/` — maintenance and project setup

Examples:

- `feature/node-registration`
- `fix/heartbeat-timeout`
- `docs/architecture-update`

## Commit Style

Use short, descriptive commit messages:

- `feat:` — new functionality
- `fix:` — bug fix
- `docs:` — documentation
- `test:` — tests
- `refactor:` — code restructuring
- `chore:` — maintenance or setup

Examples:

`feat: add node registration endpoint`

`fix: handle expired node heartbeats`

`docs: document initial cluster architecture`
